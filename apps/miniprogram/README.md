# 微信小程序录音端

本目录是原生微信小程序，面向 `COLLECTOR` 采集员，已实现微信快捷登录、数字账号密码登录、独立个人资料与头像、任务权限申请、“待处理 / 已提交 / 已完成 / 废弃数据”任务数据页、三类参考源、录音、文本复制与补充、审核领取前修改、释放备注、标记无效、恢复和只读查看，以及独立“统计”页。小程序身份 ID 固定为 `MINI-...`，角色由服务端鉴权固定为 COLLECTOR，不作为小程序用户文档字段保存。作业页直接读取任务响应中的 `configuration`，不再请求任务版本。`TEXT` 成果允许纯文本、纯录音或两者同时提交；纯文本使用 JSON 请求，有录音时使用 multipart 上传，避免小程序手工拼接 multipart；`AUDIO` 必须提交录音且不得夹带文本。

登录页为“砚数声采”A 版，使用正式品牌图标；品牌区后先展示微信/账号登录卡片，再展示“特定范围使用说明”，使微信登录主体位于页面中部。完整说明文案为：“本小程序仅供重庆砚数科技有限公司内部员工及经项目管理员邀请、授权的录音采集人员使用，不面向公众开放注册或提供服务。首次使用微信快捷登录时，须输入管理员提供的有效邀请码；未获邀请或邀请码无效、已停用、已用尽的人员无法创建账号或进入小程序。已开通数字账号的人员可使用账号密码登录。进入录音任务前，系统仍会校验对应任务授权。”默认使用微信快捷登录，“切换账号登录 ▸ / 切换微信登录 ▸”位于各登录模式标题行右侧。已有微信用户直接登录；新微信身份收到 `INVITATION_REQUIRED` 后打开邀请码弹层，提交时重新调用 `wx.login` 获取临时 code，失败保留输入，成功后才保存会话。首次准入成功后，服务端会在用户记录中保存邀请码名称和末四位等脱敏来源，完整邀请码不会写入用户记录或返回小程序。邀请码弹层操作区使用响应式双列，验证按钮比取消按钮更宽，按钮文字固定单行显示。数字账号登录和会话接管保持不变。资料完成只要求姓名；姓名去除首尾空格后按精确值全局唯一，英文大小写不同允许共存，重复时显示服务端“该姓名已被使用”提示且不保存。数字账号和密码为成对可选字段，可在首次保存时留空，也可稍后后补一次，不影响申请权限、领取和处理任务。数字账号旁的问号说明其用于脱离微信快捷登录的可选登录方式。头像卡使用原生 `button open-type="chooseAvatar"`，选择后先进入应用内预览，确认后才上传；小程序端不再提供恢复默认头像入口，读取失败仍静默回退本地默认头像。

当前账号资料摘要随不透明 token 一起保存在 `recSession.user`。已完善资料时，任务入口直接使用缓存并静默刷新，断网不会误判为资料未完善；没有完整缓存且联网失败时只显示网络 Toast。退出登录和修改密码重新登录会删除整个会话缓存，微信登录、数字账号登录或接管成功会整体覆盖旧账号资料。姓名、资料完成状态及头像元数据更新后同步写回缓存，但不额外缓存头像二进制文件。

底部导航固定为“任务 / 统计 / 我的”。点击“我的”直接进入标题为“个人资料设置”的完整资料界面，不再经过资料摘要或第二层页面；头像、基本信息、数字账号、密码修改和退出登录均在同一 Tab 内。基本信息标题右侧始终显示资料状态，未完成姓名设置时为橙色“待完善”，完成后为绿色“已完善”。基本信息区展示完整 `MINI-...` userId，直接点击整行会复制完整值并提示“用户 ID 已复制”，剪贴板失败或 ID 缺失时提示“复制失败，请重试”。任务入口发现资料未完善时，确认“去设置”会直接切换到“我的”Tab。

“统计”页每次进入都重新查询数据库，并默认选择最近提交过的任务和“全部日期”。用户可通过原生日期选择器限定单个业务日，也可清除日期恢复全量；业务日按 Asia/Shanghai 04:00 至次日 04:00 统计，凌晨 0–3 点仍归属前一天。切换任务、选择/清除日期都会重新读取整页数据。页面按当前 assignment 统计任务总提交条数、当前已完成条数、当前结果录音时长、参考音频时长和参考视频时长；没有对应媒体时按 0 统计。每日明细以当前 assignment 的首次提交业务日期分段，不重复累计返修或覆盖提交。页面只展示最近 3 条提交记录，点击记录进入对应作业，点击“更多”进入该任务的完整倒序提交列表，并继承当前日期条件。管理员将条目释放回数据池后，原采集员的当前统计不再包含该条目；历史提交和操作记录仍保留。

任务大厅不展示全局“当前有未完成作业”卡片，也不缓存全局当前条目。每个任务通过“查看任务”进入自己的“任务数据”页；每次点击“领取新数据”都会使用新的幂等键领取一条 AVAILABLE 数据，同一采集员可在同一或不同任务中同时持有多条普通待录制作业。四个页签固定为：`PENDING`（待录制和待返修）、`SUBMITTED`（可播放、重新录制并保存修改）、`FINISHED`（待审核和已完成，只读播放和查看文本）、`DISCARDED`（本人废弃数据，只读查看和恢复）。每个页签在自身状态集合内统一按最新修改时间倒序、条目序号升序，不再按状态分组；服务端每页固定读取 10 条。提交修改若与审核领取并发并收到 `STALE_STATE`，页面刷新最新状态并提示状态已变化；待审核、已完成和已废弃隐藏录制、文本编辑与提交。

录音作业页使用固定高度的四状态卡片骨架：待录音、录音中、已暂停和处理中切换时，状态文字、波形及“暂停/继续/结束”控制不会上下跳动。录音完成后同时提供“重新录制”和纯文字“删除录音”按钮；删除需要二次确认，只清空当前录音、时长和播放器，文本结果保持不变。本次新录音尽力清理本地文件，清理失败不阻塞页面；已提交状态删除原录音后，只有继续点击“保存修改”才会同步移除服务端录音，直接离开页面不会修改服务端。文字成果可删除误录音后只提交文本，纯音频成果仍必须重新录制。顶部右侧依次显示状态、三角回收图标和垃圾桶图标：三角回收用于释放回数据池并可填写 200 字以内备注，垃圾桶用于标记无效，必须填写 1–200 字原因并二次确认。废弃详情固定展示原因、操作人和时间，底部提供恢复按钮。参考文本、参考音频、参考视频区域始终存在，缺失项显示“无”；参考文本支持长按选择复制，并提供“复制全文”按钮。

实时波形只使用当前 PCM 帧，不保存历史音量或移动平均。RMS 不超过 `0.02` 时，7 根柱子全部保持 `8rpx` 平线；有声时按中心最高、左右对称的固定权重展开，RMS 达到 `0.25` 后按最高幅度显示，柱高限制在 `100rpx`。开始录音、暂停和错误时立即恢复平线，继续录音后由下一帧声音重新驱动。

参考音频、当前录制结果和已提交/只读结果统一使用本地 `audio-player` 组件，由 `wx.createInnerAudioContext()` 提供播放、暂停、拖动进度、结束复位、错误提示、参考时长上报和页面卸载销毁。参考音频在 `canplay` 时若尚未取得时长，会自动进行有界延迟检测，用户无需先点击播放；换源或销毁时取消旧检测。参考视频使用原生 `<video>`，并在元数据加载后读取参考时长。URL-only 新条目直接播放 `referenceAudioUrl/referenceVideoUrl` 公网地址；历史条目没有 URL 字段时使用 `/api/media/public/reference/{mediaId}` 后端公网兼容地址，不再通过 `downloadFile` 临时目录加载参考媒体。生产 URL 必须来自微信后台配置的合法域名。每次提交都携带参考音频和参考视频时长；存在参考源却未取得正时长时阻止提交，不存在的参考类型固定上报 0。后端第一次提交保存基准值，后续提交误差不超过 1000 毫秒时沿用基准值，超过时拒绝。参考音频、参考视频和已提交录音独立加载，单项失败不阻断作业主体或另一媒体。不同音频播放器也彼此独立，可同时播放；界面只显示一个动态时间值，不再使用原生 `<audio>` 或重复展示时长。WAV 采用流式写入，MP3 使用固定版本 `@breezystack/lamejs@1.2.7` 的本地 vendor 文件，运行时不依赖网络。

待录制和待返修作业在提交按钮上方显示胶囊样式“提交后自动领取下一条”开关，首次默认开启并用 `autoClaimNextEnabled` 本地记忆。开启时提交成功会使用稳定幂等键领取并 `redirectTo` 下一条；弱网重试复用同一键。池空、权限失效、任务停止或其他领取失败会 Toast 提示并进入当前任务数据页；关闭时返回上一页。已提交状态的“保存修改”不显示该开关，也不自动领取。

录音、参考音频、参考视频和录制结果完全独立，可同时运行并产生预期的声音混叠；开始或继续任一媒体不再暂停其他媒体。离开作业页后，音频组件、原生视频和录音会话仍分别按生命周期停止并释放资源。录音暂停继续保持平线且不写入 PCM。录音区外层最小高度为 `460rpx`、状态层为 `392rpx`，作业页专用文字输入框固定为 `200rpx`，不影响其他页面。登录、领取、提交、录音保存和播放等操作错误使用悬浮 Toast，不再在卡片底部追加错误文字；只有页面整体数据加载失败保留带“重新加载”的阻塞状态。作业页断网加载时显示“网络链接失败，请检查网络。”，其他业务加载错误仍保留服务端文案。

播放器初始化期间可能短暂收到空资源路径；空路径只复位组件显示，不得写入 `InnerAudioContext.src`，避免微信音频内核尝试解码空资源并产生 `Unable to decode audio data`。只有有效的本地临时文件路径才会交给音频上下文。

## 本地导入

1. 复制 `project.config.example.json` 为 `project.config.json`，在本地文件中填写测试 AppID。
2. 需要修改 API 地址时，新建不受 Git 跟踪的 `config/private.js`：

   ```js
   module.exports = { apiBaseUrl: 'https://your-test-api.example.com' }
   ```

3. 在微信开发者工具中导入 `apps/miniprogram`。本地 HTTP 联调可暂时关闭“不校验合法域名”；真机和正式环境必须使用 HTTPS，并在微信后台配置 request、uploadFile、downloadFile 以及参考音频/视频公网地址对应的合法域名。

AppSecret 只存在后端环境变量 `WECHAT_APP_SECRET`，绝不得放入小程序。`project.config.json`、`project.private.config.json` 和 `config/private.js` 均已忽略。

录音授权由实际调用 `wx.getRecorderManager()` 开始录音时触发；不要在 `app.json.permission` 中声明无效的 `scope.record`。麦克风被拒绝后的重新授权仍需在开发者工具和真机验证。

## 品牌头像

小程序名称使用“砚数声采”，头像资产位于：

- `assets/branding/yanshu-avatar-144.png`：144×144 PNG，文件小于 2MB，用于微信小程序后台上传。
- `assets/branding/yanshu-avatar.svg`：同构矢量源文件，用于代码引用或后续无损导出。

头像固定使用暖米白背景、墨黑录音声纹、朱砂红录音点和“砚数”文字。修改时应同步更新 PNG 与 SVG，并重新检查 48px 列表尺寸的可读性。

## 按钮圆角与下拉刷新

小程序全局清除微信原生 `button::after` 边框，普通文字按钮统一使用中等圆角矩形，迷你按钮使用独立尺寸；任务页筛选项保持胶囊形，播放、录音和录音控制按钮保持圆形。新增按钮时应复用现有基础类或明确覆盖尺寸与圆角，不要依赖原生按钮默认边框。

下拉刷新只在数据浏览页开启：任务大厅、任务数据、统计和完整提交记录。任务数据页使用“上一页 / 可选择的第 X 页，共 Y 页 / 下一页”显式分页，可直接选择任意页；切换“待处理 / 已提交 / 已完成”页签时回到第一页，下拉刷新保持当前页，数据减少导致页码越界时自动回到新的最后一页，请求失败时保留当前列表。登录、我的资料设置和录音作业页不得开启下拉刷新，避免打断输入或录音。

```powershell
cd apps/miniprogram
node --test tests/*.test.js
```
